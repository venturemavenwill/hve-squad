- **Independent workstreams made the user wait for each other.** With the new `delivery=background` input, in interactive mode only, independent workstreams with disjoint write sets run as background subagents under one confirmation while the coordinator keeps talking to the user; `delivery=background` never overrides disjointness. Coordinator-only gates run in the foreground first, and only a bounded workstream or one with a confirmed plan launches in background. The coordinator dispatches a bounded workstream's owners and its named reviewer directly; only a multi-stage workstream uses the new non-user-invocable `Squad Workstream Lead`, which carries the Squad Lead's pin and no `tools:` list, copies each owner's `Model` cell as written, picks no model, and writes no squad state. The coordinator waits with `read_agent`, verifies each artifact and the review verdict on disk, and hands each workstream's payload to the Squad Scribe, which runs `Write-SquadHandoff.ps1`, one hand-off at a time per squad root. The script accepts an optional `workstream` id (with `launchedAt` and `since`), requires a review-class record for it, refuses a deliverable already credited and not modified since, and records the lead's own turns from `orchestration.leadConsumption` as a second orchestration block. `Get-SquadDispatchBrief.ps1 -Background` embeds the procedure. See *Background Workstreams Procedure* in `squad-src/.github/skills/squad/references/gates-and-modes.md`.
