- **Every task paid for the full Research -> Plan pipeline, and independent deliverables ran one at a time.** In interactive mode only (not `mode=autonomous` or `mode=autopilot`), a new bounded lane waives Research and Plan only when every strict criterion holds (exact files and change named, no open questions, one owner or disjoint write sets, no council domain, no gate trigger); the owning role is still dispatched and `tester` still closes, any doubt or the new `pipeline=full` input keeps the full pipeline, and the Scribe records `Route: bounded` with the criteria check. The lane is a process option only: it decides which stages run, never which model runs them, so every dispatch keeps the model its routing mode resolves. A bounded owner brief names the full write set, the change, the validation command, and the change record, allows a reference search for changed symbols, and returns `blocked: not bounded` when a dependent needs a change; the Implementor and Technical Writer collapse their phase loop for it. A Lead plan with `deliverable-fan-out` (or a bounded request listing independent items) with disjoint write sets may now run its owners concurrently, confirmed once per batch (the confirmation lists every owner, tier, and write set; an `escalate`-tier owner is never batched). Ordinary turns read less: `profiles-and-packs.md` only for Init, a roster change, or a pack proposal, and each file once.
